# Modelo de dados — Mekano Registry Service API

**Banco:** `mekano_registry` (PostgreSQL 16)
**Migrations:** `registry-infrastructure/src/main/resources/db/migration`

---

## 1. Princípios

- Uma **migration final por tabela**, já com todas as colunas, tipos, constraints e índices.
- Sem migrations de correção nesta fase acadêmica.
- `BIGINT GENERATED BY DEFAULT AS IDENTITY` como PK.
- `UUID` único exposto na API.
- Soft delete com `is_active` e `deleted_at`.
- Auditoria com `created_at`, `updated_at`, `created_by`, `updated_by`.
- Índices únicos **parciais** para campos únicos entre registros ativos.
- **Nenhum campo de estoque** na tabela de peças.

---

## 5. Convenções de migration

- Usar `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- Não usar `BIGSERIAL`.
- Não agrupar múltiplos `ADD COLUMN` em uma linha.
- Nomear constraints e índices explicitamente.
- `TIMESTAMP` sem timezone, seguindo o padrão do monólito.
- `NUMERIC(12,2)` para valores monetários.
- `CHAR(44)` reservado para chave de NF no Supplies (não no Registry).
